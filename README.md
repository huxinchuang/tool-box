# tool-box 工具箱 - 微信小程序

## 项目简介

一个可扩展的**微信小程序工具箱**，首页展示所有工具入口，目前包含两个工具：

| 工具 | 说明 |
|------|------|
| 🚚 **货车运输记账** | 逐条录入运输记录，自动计算总价，智能合并相同车次的数据，并生成可保存的 Excel 风格表格图片 |
| 🎮 **游戏币管理** | 账号密码登录，玩家查看游戏币余额与变动历史；管理员可创建玩家账号、给玩家加/减游戏币 |

---

# 一、工具箱首页

首页 `pages/home/home` 以卡片形式展示全部工具入口，点击进入对应工具。
游戏币管理需要登录，未登录时点击入口会先跳转登录页；已登录则直接进入余额页。

# 二、货车运输记账工具

---

## 主要功能

### 1. 记录录入
- **输入字段**：日期、车号、规格、件数、重量（吨）、单价（元/吨）
- **自动计算**：总价 = 重量 × 单价
- **智能补全**：
  - 若**日期为空**，自动继承上一条记录的日期（首条记录允许为空，但会留空）
  - 若**车号为空**，自动继承上一条记录的车号（首条车号**必须填写**）
- **提交后清空**：录入一条记录后，所有输入框清空，便于连续录入

### 2. 数据合并规则（重点）
当**连续两条或以上记录**满足以下**四个字段完全相同**时：
- 日期
- 车号
- 重量
- 单价

则：
- **后续记录**的“重量/吨”、“单价”、“总价”单元格显示为空（不显示数值）
- 但后续记录的“规格”、“件数”正常显示
- 在**合计金额**和**运费重量**计算中，只计**该组的第一条记录**（重复的后续记录不重复累加）

> 示例：  
> 记录 A：2026-03-12，京A123，水泥，10吨，50元/吨，总价500  
> 记录 B：2026-03-12，京A123，水泥（另一规格），10吨，50元/吨，总价500  
> 则表格中 B 的重量、单价、总价显示为空，合计金额只加一次500元。

### 3. 运费计算
- **运费重量**：遍历所有合并组，每组只取一次重量（去重求和）
- **运费单价**：用户可自定义（默认30元/吨）
- **运费总价** = 运费重量 × 运费单价
- 运费行显示在表格末尾，行背景为浅黄色

### 4. 底部结欠行
- 显示格式：`{最新日期}止合计结欠货款 {总金额} 元`
- **最新日期**：取所有非空日期中的最大值（若无日期则显示“至今”）
- **总金额** = 所有合并组的总价之和 + 运费总价

### 5. 附录功能
- 提供多行文本输入框，可填写备注信息（如“以上数据已核对”）
- 内容**自动保存**到本地缓存，下次打开小程序自动加载
- 附录文本会显示在表格图片的最底部

### 6. 生成图片
- 点击“生成表格图片”按钮，将当前预览表格（包含所有数据行、运费行、结欠行、附录）渲染为 PNG 图片
- 图片尺寸自动适应内容，最大不超过 4096×4096
- 生成后显示缩略图，支持**点击预览**和**保存到相册**

### 7. 删除记录
- 点击“删除上一行”按钮，删除最后一条**原始录入记录**（非合并后的行）
- 删除后自动重新计算合并与合计

## 边界情况与规则定义

| 场景 | 处理方式 |
|------|----------|
| **首条记录车号为空** | 提示“请填写车号（首条记录不能为空）”，拒绝添加 |
| **日期格式错误** | 支持 `20260312` 或 `2026-03-12`，其他格式提示错误 |
| **日期为空** | 存储为空字符串，预览时显示空白；空日期之间可以相互合并（视为相同） |
| **车号为空（非首条）** | 自动继承上一条记录的车号 |
| **重量或单价不是数字** | 提示“重量和单价必须是数字”，拒绝添加 |
| **规格、重量、单价任一为空** | 提示“规格、重量、单价不能为空”，拒绝添加 |
| **件数为空** | 存储为空字符串，正常显示 |
| **合并条件** | 仅当**连续且完全相同**（日期、车号、重量、单价）才触发隐藏，不跨间隔 |
| **合计金额计算** | 基于合并组（每组只计一次），而非原始记录条数 |
| **运费重量计算** | 同样基于合并组去重（相邻且重量+单价相同只计一次） |
| **最新日期获取** | 取所有非空日期的最大值（按字符串排序即可，格式 YYYY-MM-DD） |
| **图片尺寸限制** | 表格总宽或总高超过 4096px 时提示“表格过大”，拒绝生成 |
| **生成图片失败** | 显示错误信息（如 canvas 获取失败、路径无效等） |
| **保存图片权限** | 若用户拒绝授权，弹窗引导前往设置开启 |

# 三、游戏币管理工具

## 角色说明

- **管理员**（默认 `admin`，仅一人）：创建玩家账号、给玩家加/减游戏币（可填备注）、查看任意玩家的变动历史
- **玩家**：账号密码登录后查看自己的游戏币余额与变动历史

## 主要功能

1. **登录/登出**：账号密码登录，token 有效 30 天；退出登录后 token 立即失效
2. **余额查看**：登录后首页大字展示当前游戏币余额
3. **变动历史**：分页展示每笔变动（时间、+/-数量、变动后余额、操作人、备注），下拉触底加载更多
4. **分组管理（管理员）**：每个玩家可创建多个余额分组（如按游戏分），分组内加减币、重命名、删除（有余额拒绝删除）
5. **分组视图（玩家）**：余额页可单选分组 / 多选多分组对比（折线图多线对比）/ 全部总和，历史按分组筛选
5. **数据安全**：密码 scrypt 加盐哈希存储；余额更新与流水写入同一事务，保证原子性；玩家越权访问管理接口返回 403

## 接口一览（前缀 /api）

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | /auth/login | 公开 | 登录，返回 token + 用户信息 |
| POST | /auth/logout | 登录 | 登出 |
| GET | /auth/me | 登录 | 当前用户信息（含最新余额） |
| GET | /balance | 登录 | 当前余额 |
| GET | /transactions?playerId=&offset=&limit= | 登录 | 变动历史（玩家只能查自己，管理员可查任意玩家） |
| GET | /admin/players | 管理员 | 玩家列表 |
| POST | /admin/players | 管理员 | 创建玩家 {username, password, nickname} |
| POST | /admin/adjust | 管理员 | 加/减币 {playerId, groupId, amount(±) 或 base+percent, remark} |
| GET/POST | /admin/groups | 管理员 | 查询/创建分组 {playerId, name} |
| PUT/DELETE | /admin/groups/:id | 管理员 | 重命名/删除分组（有余额拒删） |
| GET | /groups | 登录 | 我的分组（含余额） |

## 技术要点

- 基于微信小程序原生框架（基础库 ≥ 2.9.0，支持 Canvas 2D）
- 货车记账数据存储：`wx.setStorageSync` / `wx.getStorageSync` 保存运费单价和附录
- 图片生成：`canvas` 绘制表格，`wx.canvasToTempFilePath` 导出临时文件
- 日期处理：统一标准化为 `YYYY-MM-DD`，显示转为 `YYYY年M月D日`
- 游戏币后端：Node.js + Express + SQLite（Node 24 内置 `node:sqlite`，零安装）
- 游戏币余额为整数，避免浮点误差；每次变动写流水并记录变动后余额快照

## 如何运行

### 1. 启动后端服务（游戏币管理依赖）

```bash
cd server
npm install        # 安装依赖（仅 express）
npm run seed       # 初始化默认管理员账号（幂等）
npm start          # 启动 API 服务，默认 http://127.0.0.1:3000
```

- 数据库为 SQLite 文件（`server/data/game.db`），首次启动自动创建，无需安装数据库
- 默认管理员账号：`admin` / `admin888`（可用环境变量 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 覆盖，正式使用前请修改）
- 可用 `bash test-api.sh` 运行后端接口集成测试（23 个用例）
- 迁移到 MySQL 时只需改写 `server/db.js`，表结构差异已在 `server/schema.sql` 中标注

### 2. 运行小程序

1. 使用微信开发者工具打开项目根目录
2. 开发环境需在「详情 → 本地设置」勾选 **不校验合法域名**（后端地址为 `http://127.0.0.1:3000`，配置在 `utils/config.js`）
3. 编译运行：首页 → 选择工具

### 3. 部署到 Ubuntu 服务器（生产环境）

后端已支持一键部署到 Linux 服务器（SQLite 数据库随代码一起迁移，零安装）：

```bash
cd deploy
SERVER_HOST=你的服务器IP SERVER_PASS='你的密码' bash deploy.sh
```

部署内容：
- 上传 `server/` 全部代码 + `data/game.db` 数据库到服务器 `~/tool-box-server`
- 自动 `npm install` 并注册 **systemd 服务**（`toolbox-server`：开机自启、崩溃自动重启）
- 服务监听 `3000` 端口（Node 22 使用 `--experimental-sqlite` 标志）

部署后注意：
- 需在云服务器安全组**放行 3000 端口**（腾讯云控制台 → 安全组 → 添加入站规则）
- 小程序正式使用需 HTTPS + 备案域名，届时把 `utils/config.js` 的 `baseUrl` 改为线上地址
- 数据库文件在服务器 `~/tool-box-server/data/game.db`，备份该文件即备份全部数据

## 注意事项

- 货车记账工具依赖 Canvas 2D，请确保微信客户端版本支持
- 生成的图片仅保存在本地临时目录，需用户主动“保存到相册”才能持久化
- 运费单价和附录的本地缓存与设备绑定，卸载小程序后可能清除
- 游戏币管理正式上线需将后端部署到 HTTPS + 备案域名，并把 `utils/config.js` 的 `baseUrl` 改为线上地址
